## VPS 到底是什么，它凭什么是"中间那一档"

VPS 是从一台物理服务器上切出来的虚拟服务器。你拿到的是 root 权限、一个独立 IP，以及一块固定的 CPU、内存和硬盘配额。装什么系统、跑什么程序、开几个网站，全由你决定，不需要跟别人共享一个控制面板。

它的位置刚好卡在中间：比虚拟主机自由（虚拟主机只给你网站目录，装个扩展都要看服务商脸色），比独立服务器便宜（不用自己维护硬件）。个人建站、跑小工具、做开发测试环境，VPS 基本是默认选项。

代价是它不负责"帮你搞定"。系统要自己装，安全更新要自己打，出问题要自己看日志。这也是为什么新手买完第一台 VPS 后最常见的状态是：SSH 连上了，然后不知道下一步干什么。

## 买之前先定三件事，配置表自然就有答案

### 第一件：用途决定内存下限

内存是 VPS 上最先见底的资源，比 CPU 更容易成为瓶颈。按经验给几档：

- **512MB**：能跑，但很紧。装个面板、开个数据库，剩余空间就不多了。只适合纯测试、一次性任务。
- **1GB**：静态博客、轻量代理、个人学习环境的舒服起点。每天几百 PV 的站点，1GB 绰绰有余。
- **2GB**：WordPress 这类动态站、小型数据库、轻量应用后端。装完主题和插件之后还有余量。
- **4GB**：多个站点并行、中等规模的数据库。
- **8GB 以上**：资源密集型应用，或者一台机器跑多种用途。

新手最容易犯的错是"配置越高越好"。你跑一个每天几百访问量的博客，1GB 和 4GB 的差别主要体现在账单上，不在访问速度上。

### 第二件：用户在哪，决定机房

这条原则没有例外：机房离目标用户越近，延迟越低。延迟不是抽象指标，它直接决定页面打开时那零点几秒的等待感。

反过来说，如果访客主要在中国大陆，你买一台新加坡或者美国西海岸的机器，物理距离带来的延迟是优化不掉的。

**机房在购买时就定死了，后续不能直接换。** 想换只能新开一台目标机房的机器，把数据迁过去，再取消旧的。所以这一步必须在付款前想清楚，不能指望"以后再说"。

### 第三件：预算决定计费周期

年付单价永远比月付便宜，但年付也意味着你把决定权一次性交出去了。判断标准很简单：这台机器你确定会用满一年吗？如果不确定，先月付跑一两个月，确认线路和性能符合预期再转年付。
